# ملاحظات تقنية

## RouterOS v6
الصفحات ثابتة HTML/CSS/JS ومتوافقة مع متغيرات HotSpot القياسية مثل $(username)، $(profile)، $(bytes-in-nice)، $(bytes-out-nice)، $(session-time-left) وغيرها.

## السرعة
واجهة المستخدم لا تدّعي أن JavaScript يستطيع تعديل RouterOS مباشرة. التطبيق الحقيقي يتم عبر controller/RouterOSApi.php باستخدام RouterOS API. بعد تغيير profile يتم فصل active session حتى يعاد تطبيق rate-limit.

## اسم المستخدم فقط
`name-only-login.rsc` يضبط login-by=http-pap لملف HotSpot المحدد. يجب إنشاء حسابات المستخدمين بدون كلمة مرور إذا كان هذا هو الأسلوب المطلوب.

## سجل الكروت
السجل محلي على الجهاز ويحتفظ بآخر 8 أرقام فقط.

## Google Play
الحظر per-client يعتمد على عنوان IP الحالي وعناوين DNS التي يتم حلها لحظة الضغط. ليس بديلاً عن MDM ولا يمكنه ضمان منع DoH/DoT أو كل CDN.

## الخطوط
الخطوط محلية داخل fonts ولا تعتمد على Google Fonts أو CDN، حتى تعمل الصفحة قبل تسجيل الدخول.


## إصلاح تسجيل الدخول (اسم المستخدم فقط)
- إرسال نموذج HotSpot لا يتوقف إذا تعذّر الاتصال بوحدة التحكم الخاصة بتغيير السرعة.
- حقل password يرسل فارغاً عمداً، ويجب أن يكون حساب HotSpot/User Manager مهيأً لقبول كلمة مرور فارغة.
- في HotSpot profile استخدم `login-by=http-pap` (أو أضف `http-pap` إلى طرق الدخول الحالية بدلاً من استبدالها إن كنت تريد الإبقاء على الطرق الأخرى).
- هذا لا يتجاوز المصادقة ولا ينشئ حسابات تلقائياً؛ يجب إعداد حساب المستخدم في مصدر المصادقة.
- لا يمكن ضمان دعم «كل الإصدارات» بإعداد واحد: User Manager القديم في RouterOS v6 يختلف عن User Manager v7. اختبر حساباً تجريبياً على إصدار الراوتر لديك، وتأكد من أن سياسة RADIUS/الحساب تقبل كلمة مرور فارغة.
